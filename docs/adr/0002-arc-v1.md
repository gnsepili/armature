# ADR 0002 — ARC v1: AG-UI events and Agent Protocol naming

**Status:** Accepted

## Context

Every generated app must expose one runtime contract (ARC) that the playground, terminal chat,
eval runner, and conformance suite drive, regardless of framework. The PRD asks ARC to be a thin
profile of existing standards, verified during the E04 spike.

Verified against `@ag-ui/core` 1.0.4 (protocol 1.0):

- Lifecycle events: `RUN_STARTED {threadId, runId}`, `RUN_FINISHED {threadId, runId, result?, outcome?, usage?}`,
  `RUN_ERROR {message, code?}`.
- `RUN_FINISHED.outcome` is `{type: "success"}`, `{type: "interrupt", interrupts: [{id, reason, toolCallId?, …}]}`,
  or `{type: "cancelled"}` — a native way to report a run paused for approval.
- `RUN_FINISHED.usage` is a native list of `{provider?, model?, inputTokens?, outputTokens?, totalTokens?}`.
- Text: `TEXT_MESSAGE_START/CONTENT/END`; tools: `TOOL_CALL_START/ARGS/END` and `TOOL_CALL_RESULT`;
  `CUSTOM {name, value}`.

## Decision

**Endpoints** use Agent Protocol naming (`/runs/wait`, `/runs/stream`, `/runs/{id}`,
`/runs/{id}/resume`, `/threads/{id}`) plus `/health` and `/manifest`. FastAPI serves `/docs`.

**Streaming** is SSE with one JSON AG-UI event per `data:` line. Every event must validate against
`EventSchema` from `@ag-ui/core/schemas`.

**Approvals** use both mechanisms: a `CUSTOM armature.approval_required {run_id, approvals[]}`
event (easy for simple clients) followed by `RUN_FINISHED` with the native `interrupt` outcome,
one interrupt per pending tool call, `id = toolCallId`, `reason = "tool_approval"`.
Resume is `POST /runs/{id}/resume {decisions: [{tool_call_id, approve, edited_args?}], stream?}`
on the same `run_id`.

**Usage** is reported per model call as `CUSTOM armature.usage {model, input_tokens,
output_tokens, cost_usd}` — `cost_usd: null` means not measured, never a guess — and in total on
`RUN_FINISHED.usage`.

**Errors**: `RUN_ERROR.code` is one of `limit_exceeded`, `timeout`, `model_error`, `tool_error`,
`structured_output_invalid`, `invalid_request`, `internal`. A failed run's record keeps its partial
messages and tool calls.

**Run records** (`GET /runs/{id}`) carry spans with an `invoke_agent` root and `chat` /
`execute_tool` descendants, named after the OpenTelemetry GenAI semantic conventions.

**Eval metadata** (`metadata.eval = {case_id, trial, fixtures, stubs}`) is accepted only when
`ARMATURE_EVAL_MODE=1` and the profile is not `production`; otherwise the app answers HTTP 400.

`arc_version` is the integer `1`. The JSON Schemas live in `schemas/arc-*.schema.json`, generated
from `packages/arc/src/types.ts`; the conformance suite (`packages/arc/src/conformance.ts`) is
versioned with them and is proven against a TypeScript reference server in the package tests.

## Consequences

- Any AG-UI client can render an Armature app's stream without Armature code.
- Adding an event type or field is backwards compatible; renaming or removing one needs ARC v2.
- Edited arguments on resume are optional per framework and advertised through
  `manifest.capabilities.edited_args`.
